Franquicias

Dos elementos separados: Propuestas de reposición (la venta del cliente vs su stock) y Pedido de venta (calzado por curva de talles).

Cómo funciona (mismo circuito que Reposición sugerida)

  1. 1 · Cliente obligatorio: apenas entrás hay que seleccionar el cliente (ID Cliente de MITO). Hasta que no lo elegís, la tabla y los filtros quedan bloqueados. Ese ID Cliente es el que va en la cabecera del pedido de venta que se carga en Dragon. 1.990 clientes reales
  2. 2 · Filtros multi-selección de Temporada (Verano / Continuo / Invierno / Atemporal), Material, Grupo y Familia (de DWH.dbo.vw_DIM_ARTICULO). Podés tildar varios en cada uno; se combinan y filtran la tabla al instante.
  3. 3 · Curva de talles: dos solapas (zapatillas talle simple / chanclas y slippers talle doble). Cada celda muestra arriba el stock de MITO del talle y abajo el input para cargar los pares.
  4. 4 · Armar link y mandar por WhatsApp: se guarda la propuesta con el cliente elegido y sale el link /p/:token.
  5. 5 · El cliente confirma desde el link (marca sí/no y cantidades, topeadas al stock de MITO).
  6. 6 · Alta en Dragon automática: el puente toma las confirmadas y las carga como Pedido de Venta en DRAGONFISH_MITO por la API REST (POST /Pedido/). Después podés seguir el estado desde la pantalla.

¿A qué cliente le armás la reposición?

Su stock se lee de la sucursal que le corresponde (ej. 01140 → CF Ushuaia / DRAGONFISH_CFU). El sugerido sale de su venta − su stock, topeado por el stock de MITO.

Ventas de la franquicia vs su stock (bajado de MITO)

  1. Sale de VISTAS_CONSOLIDADAS.dbo.venta_franquicias: lo que vendió el cliente en el período.
  2. Se compara con el stock real del cliente (vw_STOCK_SUCURSALES_REAL, la sucursal que le toca al cliente elegido) y se sugiere reponer la diferencia.
  3. El sugerido se topea con el stock real de MITO: sólo SKUs con stock MITO > 0 y sugerido > 0.
  4. El precio de cada SKU sale de vw_ARTICULOS_MITO (la misma que usa F12), y con él se calcula el valor sugerido.
  5. El resultado es una propuesta que el cliente confirma por link y se carga como Pedido de Venta en Dragon. 16/09/2026 → 15/10/2026

A qué base de datos pertenece cada cliente

  1. Cada cliente se asocia a una base de datos (ej. DRAGONFISH_CFU).
  2. Cada base dice de qué sucursal de stock se lee el stock del cliente (ej. CAPTAIN FIN USHUAIA).
  3. Con eso, la reposición del cliente sale de su venta − su stock (de SU sucursal), topeado por el stock de MITO.
  4. La asociación se guarda en la tabla real franquicias_clientes de Supabase (pendiente de aplicar).
