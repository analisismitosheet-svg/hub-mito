Cómo lo haríamos (sin inventar nada nuevo)

1Tarea diariaVercel Cron a las 08:30 → /api/reposicion-diaria.
2CalcularPor cada cliente con base: ventas de ayer, su stock y el de MITO.
3ArmarSugerido = vendido − stock cliente, topeado al stock de MITO.
4PropuestaSe crea la P-00N con sus ítems y el token del link.
5WhatsAppAPI de WhatsApp (plantilla aprobada) con el resumen y el link.
6ConfirmaciónEl cliente confirma → el puente la carga en Dragon como hoy.
  1. Una sola vez por día: clave única cliente_id + fecha en la propuesta. Si la tarea corre dos veces, no duplica ni vuelve a mandar.
  2. No manda si no hay nada: sin ventas de ayer o sin sugeridos > 0, ese cliente no recibe mensaje (y queda el detalle en el historial).
  3. Urgentes primero: stock cliente 0 + vendió + hay más de 1 en MITO. Se listan arriba con 🔴.
  4. Mismo circuito: no cambia nada del link, la confirmación ni el alta en Dragon. Solo se automatiza el armado y el envío.
  5. Si la API falla: la propuesta queda creada y el hub muestra “Mandar a mano” con el link (como hoy).

Lo que hay que definir antes de implementarlo

  • Número: ¿sale de un número nuevo de MITO o del WhatsApp que ya usan? (la API no puede usar un número que esté en la app común).
  • Plantilla: Meta tiene que aprobar el texto. El link va como botón de URL, no como texto suelto, para que no lo marque como spam.
  • Contactos: se mandan a los contactos cargados en cada franquicia (los mismos de las propuestas). Si hay varios, al principal y copia al resto.
  • Horario: 08:30 de Argentina. Si el cliente no confirmó, a las 24 h se le puede mandar un recordatorio (opcional).
