🗄️ 1 · Datos (Supabase)

  • Tabla nueva mayorista_armados: un registro por pedido mientras esté activo.
  • Insert atómico (on conflict pedido) para que no se pida dos veces.
  • Un registro por pedido activo (pedido_codigo unique): varios pedidos a la vez = varias filas, todas con la misma prioridad si se mandan juntos.
  • Cuando alguien acepta: update condicionado a estado='pendiente' → sólo uno gana la carrera.
  • Orden de lectura en los celulares: order by case prioridad when 'urgente' then 0 when 'normal' then 1 else 2 end, created_at
-- crea la tarea y avisa (RLS: repo la lee, todos la aceptan)
create table mayorista_armados (
  id           uuid primary key default gen_random_uuid(),
  pedido_codigo text not null unique,   -- '10032'
  cliente      text,
  prioridad    text not null default 'normal', -- urgente|normal|baja
  estado       text not null default 'pendiente', -- pendiente|aceptado|hecho|cancelado
  solicitado_por uuid,
  aceptado_por uuid,             -- legajo que lo tomó
  observacion  text,
  created_at   timestamptz default now(),
  aceptado_en  timestamptz
);

update mayorista_armados
   set estado='aceptado', aceptado_por=:yo, aceptado_en=now()
 where pedido_codigo=:pedido and estado='pendiente'
returning id;   -- 1 fila = lo tomé yo · 0 filas = ya lo tomó otro

📡 2 · Cómo se enteran (y suena)

  • Realtime de Supabase en mayorista_armados → el celular se entera en ~1 s (hoy la campana ya hace polling cada 30 s; para esto baja a 5 s o usa realtime).
  • Sonido: un archivo corto en public/ + new Audio().play() desde el click/evento (navegador bloquea autoplay si nadie tocó nada).
  • Vibración: navigator.vibrate([200,80,200]) en Android.
  • Notificación nativa: Notification.requestPermission() → banner en el celular.
  • Que suene con la app cerrada ⇒ Web Push (service worker + FCM/OneSignal) o Supabase Edge Function que mande push al crear la fila. Sin eso, sólo suena con la pestaña abierta.
insert fila→realtime broadcast→tarjeta + sonido→click Aceptar→update condicionado→los otros ven “lo tomó Juan”

🧩 3 · En la UI

  • Botón “Pedir armado”: en la barra de acciones del pedido abierto (junto a Imprimir) + uno chico en cada fila de la lista.
  • Filtro de fecha “Hoy” al lado del de periodo + ☑ Tildar todo (N): filtrás el día, tildás todos y mandás un solo “Pedir armado” (una tarea por pedido).
  • Selección múltiple: checkbox por fila; la barra azul muestra cantidad y total, y de ahí se envía todo junto.
  • Orden en el celular: las tareas se apilan por prioridad (urgente → normal → baja); a igual prioridad, la más vieja arriba. Suena con cada tarea nueva, aunque ya haya otras activas.
  • Estados visibles: Pendiente → En curso con Juan P. (4471) → Hecho. Cada vez que un legajo marca, la fila del pedido queda en verde (EN CURSO ✓ / ARMADO 🏁).
  • Avance artículo por artículo: el pedido tiene una columna Avance y una barra con unidades marcadas / totales. A medida que el legajo escanea o tilda en el celular, el pedido del mayorista se va pintando en verde línea por línea; cuando queda todo, el armado se cierra solo (🏁) y la fila entera queda verde.
  • Campana del header: suma el ítem “Armado pedido N° 10032” con la prioridad.
  • Mi Repo: se abre en la tarea nueva con botón Aceptar / Omitir; al aceptar aparece el pedido armable con escaneo.
  • Permisos: sólo rol mayorista/admin puede pedir; cualquier legajo con rol repo puede aceptar.
  • Al terminar el armado vuelve a hecho y desaparece de los celulares.
