¿Finalizar el repo?

✅ Lo que ya tenés (igual que hoy)

  • Lista de repos por local con chip del local, avance X de Y unidades y barra.
  • Repo abierto: panel fijo con nombre + cronómetro + Iniciar / Pausar / Reanudar.
  • Input del escáner (escáner inalámbrico con Enter, teclado o cámara) y feedback del último escaneo con Deshacer.
  • Faltan escanear / Escaneados, contador grande que sube y botón Finalizar repo (verde si está todo, rojo con faltantes).
  • Cierres con faltantes → se marcan ✕, como ahora.

🔔 Lo nuevo (los armados)

  • Arriba de todo: sección Armados pedidos con la tarjeta de cada tarea: prioridad, N° de pedido, cliente y observación + botones Acepto / Omitir.
  • Al aceptar se convierte en una tarjeta más del repo (con barra de avance) y entra al panel abierto de siempre: cronómetro, escáner, faltan/escaneados, finalizar.
  • Los artículos del pedido se van marcando línea por línea con cada escaneo.
  • Finalizar armado avisa al mayorista: el pedido pasa a hecho 🏁 (o “terminado con N faltantes”).
  • Prioridades arriba de la lista: urgente → normal → baja; suena el celular con cada tarea nueva.
  • Si mandás 10 pedidos llegan las 10 (tocá 🔟): se apilan todas arriba, ordenadas por prioridad, y las aceptás de a una — sólo una tarea se abre para escanear por vez (el cronómetro es por tarea).
  • 📷 Cámara: lee QR, Code 39, Code 128 / EAN-128 y EAN-13 — el visor muestra el formato detectado al lado del código leído.
  • ✓ Tilde al lado de cada artículo: si la cámara no lo lee y no querés escribirlo, tocás la tilde y esa línea queda marcada (con “↺ Deshacer” para deshacer).

🗄️ Cómo se apoya en lo que ya existe

  • El armado usa la misma estructura de ítems que los repos: cantidad / escaneadas / estado y el mismo RPC escaneear_codigo().
  • Sólo cambia el origen: en vez de un lote cargado, los ítems salen de pedidos_venta_items del pedido elegido.
  • Al aceptar: update … set estado='aceptado' where estado='pendiente' → sólo un legajo lo toma.
  • La sesión (iniciar/pausar/finalizar) y los tiempos se reutilizan tal cual con piso_tiempos.sql.
  • Cuando todas las líneas están marcadas → estado='hecho' y el mayorista lo ve en verde.
  • La cámara ya es html5-qrcode (ScannerCamara.tsx): hoy tiene EAN_13, EAN_8, UPC_A/E, CODE_128, CODE_39, ITF, CODABAR y QR sólo con conQr. En el armado se abre con conQr={true} y listo.
  • La tilde manual es una actualización por línea: update pedidos_venta_items set escaneadas = cantidad (mismo campo que usa hoy el escáner).
